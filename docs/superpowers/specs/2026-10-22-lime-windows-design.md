# Lime for Windows — 설계 문서

작성일: 2026-10-22
원작: https://github.com/LumenJSN/Lime (MIT, 기준 커밋 `db94ab7fd723193d5b0cdcc748fb9524526ea6bc`)

## 1. 무엇이고 왜 만드나

Lime은 macOS 메뉴바 앱이다. Finder에서 파일을 **끌고 있는 도중에 수정 키를 한 번 탭하면** 커서 위치에
원형 휠이 뜨고, 파일을 휠의 꽃잎 위에 놓으면 그 작업(형식 변환, 압축, PDF 만들기 등)이 실행된다.
결과는 원본 옆에 새 파일로 저장되고 원본은 절대 건드리지 않는다.

사용자는 윈도우 사용자이고 원작이 macOS 전용이라 쓸 수 없다. 주된 용도는 **이미지 형식 바꾸기,
이미지 → PDF, PDF → 이미지** 같은 일상적인 파일 변환이다. 우클릭 메뉴를 뒤지거나 변환 사이트에
올리는 대신, 탐색기에서 끄는 동작 하나로 끝내는 경험이 핵심이다.

원작 소스는 Swift + AppKit + Apple 프레임워크(PDFKit, Vision, Quick Look 등)라 이식할 수 없다.
**원작 소스를 동작 명세로 읽고 윈도우용으로 새로 작성한다.** (REA 같은 역공학 도구는 쓰지 않는다 —
소스가 공개돼 있다.) 원작 MIT 저작권 고지를 앱과 저장소에 포함한다.

### 성공의 모습
- 탐색기에서 PNG를 끌다가 Shift를 탭 → 휠 → JPG 꽃잎에 놓기 → 원본 옆에 JPG가 생긴다.
  이 흐름이 끊김 없이, 원작처럼 "가볍게" 느껴진다.
- 휠을 안 쓸 때는 평소 탐색기 드래그·키 동작에 아무 영향이 없다.

## 2. 목표 / 비목표 / 반목표

### 목표 (우선순위 순)

**필수**
1. 드래그 중 키 탭 → 커서 위치에 휠 → 꽃잎에 드롭 → 실행. (§4)
2. 이미지 ↔ 이미지 형식 변환, 이미지 → PDF, PDF → 이미지. (§5.1)

**있으면 좋음 (이번 범위에 포함)**
3. 오디오 형식끼리, 비디오 형식끼리 변환 (+ 비디오 → GIF/MP3).
4. 문서 형식끼리 변환과 PDF로 내보내기.
5. PPT/PPTX → PDF/JPG/PNG.
6. 스프레드시트 형식끼리 변환과 PDF로 내보내기.
7. 도구 휠: 이미지 압축, 이미지 자르기, 이미지들로 PDF 만들기, PDF 합치기, PDF 나누기.
8. 액션 휠: 선반(Shelf), 복사, 이동, 경로 복사, 터미널 열기.
9. 품질이 충분할 때만: 글자 인식 후 복사(OCR), 배경 제거. (§5.4 — 품질 기준 미달이면 넣지 않는다)

### 비목표 (이번에 안 함)
- AirDrop, 자막(SRT/VTT) 변환, 압축 파일(ZIP/TAR/GZ/RAR) 변환·풀기.
- 오디오·비디오 **편집** 도구 전부 (자르기, 음량, 음소거, 속도, 이어붙이기, 나누기, 가리기, 삐 처리, 채널, 파형 영상, 스냅샷).
- 이미지 보정·주석·배경 추가·가리기·콜라주·메타데이터 편집, QR 읽기, PDF 페이지 정리(Organize).
- Apple 전용 문서 형식(Pages, RTFD, text clipping)과 EPUB. (HEIC 이미지는 포함)
- 자동 업데이트(Sparkle 대체), 설치 프로그램, 코드 서명, 스토어 배포.
- 키 조합 변경 설정 UI, 휠 스타일 여러 개(Liquid Glass/Frosted/Solid). 스타일은 하나.
- 다국어 UI. UI 문구는 한국어 하나로 충분하다.

### 반목표 (기술적으로 돌아가도 이러면 실패)
- **원본 파일을 수정·삭제·덮어쓰기.** 어떤 경우에도 안 된다. 같은 이름이 있으면 번호를 붙인다.
- **평소 드래그를 망가뜨림.** 휠을 띄우지 않은 드래그는 Lime이 없을 때와 똑같이 동작해야 한다.
  휠을 띄운 드래그는 꽃잎 실행 또는 취소로 끝나고, 취소면 파일에 아무 일도 일어나지 않아야 한다(§4.2-4).
  드래그가 끝나면(드롭·Esc 등) 화면 덮개는 반드시 사라져야 하고, 남아서 클릭을 막으면 실패다.
  Lime이 멈추거나 죽어도 탐색기 드래그는 정상이어야 한다.
- **드래그가 아닐 때 Shift/Ctrl/Alt를 가로챔.** 평소 타이핑·단축키에 영향이 있으면 실패다.
- **Office 창이 뜨거나, 대화상자가 떠서 멈추거나, 백그라운드에 WINWORD.EXE 등이 남음.**
  사용자가 이미 열어 둔 Office 문서·창을 닫거나 건드려도 실패다.
- 변환 중 UI가 얼어붙음. 모든 작업은 백그라운드에서 돌고 취소할 수 있어야 한다.

## 3. 제약과 환경

- 대상: Windows 11 x64, 이 사용자의 PC 한 대(개인용). 실측한 환경:
  - .NET SDK 10.0.103 설치됨
  - Microsoft 365 (Word/PowerPoint/Excel, x64, COM 등록 확인됨)
  - ffmpeg가 PATH에 있음 (winget 설치)
  - Windows OCR 언어: `ko`만 설치됨 (영어 언어팩 없음)
  - GPU: NVIDIA RTX 2060 SUPER (+ AMD 내장 그래픽)
- **MS Office가 설치돼 있다는 전제로 만든다** (사용자 결정). Office가 없으면 Office 계열 변환
  꽃잎을 숨긴다. LibreOffice 대체 경로는 만들지 않는다.
- 언어·UI: **C# / .NET 10 / WPF** (내 결정 — 전역 훅·투명 오버레이·드롭 대상을 다루기 가장 쉬움).
- 트레이(알림 영역) 상주 앱. 창은 휠·진행 카드·도구 옵션 창·선반·결과 창만.

## 4. 휠과 드래그 상호작용

### 4.1 키 배치 (사용자 결정)

| 원작 (macOS) | 윈도우 | 휠 |
|---|---|---|
| ⇧ Shift | **Shift** | 변환 휠 |
| ⌘ Command | **Alt** | 도구 휠 |
| ⌃ Control | **Ctrl** | 액션 휠 |

### 4.2 동작 (원작과 동일하게)
원작 참고: `Sources/Wheel/DragGestureMonitor.swift`, `Sources/Wheel/WheelController.swift`, `README.md` "Getting started".

1. 사용자가 탐색기(또는 바탕화면 등 파일을 끌 수 있는 곳)에서 파일 하나 이상을 끌기 시작한다.
2. 끄는 도중 수정 키를 **한 번 탭**한다(누르는 순간 = 해당 키가 새로 눌린 전이에서 발동).
   누른 채 있을 필요 없다.
3. 커서 위치에 그 키의 휠이 뜬다. 키를 놓아도 휠은 그대로 있다.
4. 꽃잎 위에 놓으면 실행. 가운데 구멍이나 휠 바깥에 놓으면 취소(아무 일도 안 함).
   **(사용자 결정, 원작과 다름)** 원작은 휠 크기 창만 띄워서 바깥 드롭이 아래 Finder 폴더로 그대로 들어가지만,
   이 버전은 휠이 뜨는 순간 **화면 전체(모든 모니터)를 덮는 투명 드롭 영역**을 함께 띄워 바깥 드롭을 흡수하고 취소로 처리한다.
   즉 휠을 한 번 띄운 드래그는 다른 폴더에 놓을 수 없다. 의도치 않게 파일이 이동·복사되는 일을 막는 쪽을 택했다.
5. 휠이 떠 있는 동안 다른 키를 탭하면 그 키의 휠로 바뀐다.
6. 꽃잎 목록은 **끌고 있는 파일들 모두에 공통으로 가능한 작업만** 보여준다
   (원작 `WheelCatalog.items`). 공통 작업이 없으면 휠을 띄우지 않거나 "할 수 있는 작업 없음"을 짧게 보여준다.
7. 드래그 중이 아닐 때의 키 탭은 무시한다.

### 4.3 윈도우에서의 구현 방향과 위험
- macOS는 "드래그 대지(pasteboard)"로 끌고 있는 파일 목록을 드롭 전에 알 수 있지만, 윈도우에는 그런 공개 API가 없다.
  **방향:** 저수준 마우스·키보드 훅(`WH_MOUSE_LL`, `WH_KEYBOARD_LL`)으로 "왼쪽 버튼 누른 채 움직이는 중 + 키 탭"을 잡고,
  커서 아래에 항상 위·투명 배경의 휠 창(과 §4.2-4의 화면 전체 덮개)을 띄운다. 휠 창은 OLE 드롭 대상이라 커서가 그 위에 있으면 `DragEnter`에서
  `CF_HDROP` 파일 목록을 받는다. 그 목록으로 꽃잎을 채운다. 파일 목록이 오지 않으면(파일 드래그가 아니면) 휠을 조용히 닫는다.
- **위험 1 — 이게 실제로 되는지.** 탐색기의 `DoDragDrop` 루프 중에 새로 뜬 창이 즉시 `DragEnter`를 받는지,
  키 탭이 탐색기 쪽 드롭 효과(Shift=이동, Ctrl=복사, Alt=바로가기)나 Alt 메뉴 활성화를 일으키지 않는지 모른다.
  **→ 구현 계획의 첫 단계는 이것만 검증하는 버려도 되는 스파이크다.** 스파이크가 실패하면 다른 방식(예: 훅에서 키를 삼키기,
  드래그 소스 쪽 정보 얻기 등)을 찾고, 그래도 안 되면 사용자에게 돌아와 상호작용을 다시 정한다.
- 훅 콜백은 빨리 반환해야 한다(느리면 윈도우가 훅을 해제함). 무거운 일은 UI 스레드/백그라운드로 넘긴다.
- 관리자 권한 창 위로 끈 경우 등 UIPI 제약으로 안 되는 상황은 조용히 무시해도 된다.

### 4.4 휠 모양
- 원작 `Sources/Wheel/WheelGeometry.swift`의 형태를 따른다: 꽃잎 고리(안쪽 반지름 54, 바깥 128, 간격 5, 둥근 모서리),
  0번 꽃잎이 12시, 시계 방향, 가운데 취소 구멍. 커서가 올라간 꽃잎은 강조.
- 꽃잎 라벨: 변환은 형식 이름 대문자(`JPG`, `PDF`), 도구·액션은 짧은 한국어 이름 + 아이콘.
- 반투명 배경 하나(시스템 다크/라이트 따라감). 세부 색·아이콘·애니메이션은 구현자 재량.
- **(사용자 요구, 2026-10-22 추가)** 그래픽 완성도가 원작 수준이어야 한다. 원작 스크린샷(`Screenshots/wheel-liquid.png`,
  `wheel-solid-dark.png`)을 기준으로 삼고, 휠·창의 렌더 이미지를 사용자가 직접 보고 확인한 뒤 다음 단계로 넘어간다.

## 5. 기능 명세

### 5.0 공통 출력 규칙 (원작과 동일)
- 결과는 **원본과 같은 폴더**에 저장.
- 변환 결과: `이름.새확장자`. 이미 있으면 `이름 2.새확장자`, `이름 3...`.
- 도구 결과: 괄호 꼬리표 — `이름 (compressed).jpg`, 이미 있으면 `이름 (compressed) 2.jpg`.
  꼬리표는 원작 영어 그대로 쓴다(compressed, cropped, merged, pages, text, no background).
- 여러 결과(페이지별 이미지, PDF 나누기)는 `이름 (pages)` 폴더 안에 `이름 01.png`, `이름 02.png` … (자릿수는 페이지 수에 맞춤, 원작 `PDFTools.split` 참고).
  1쪽짜리 PDF를 이미지로 바꾸면 폴더 없이 `이름.png` 하나.
- 여러 파일을 한꺼번에 끌어 변환하면 각 파일을 따로 변환한다.
- 원본 폴더에 쓸 수 없으면 오류 카드로 알린다(다른 곳에 몰래 저장하지 않는다).

### 5.1 변환 휠 (Shift)

| 원본 | 변환 대상 | 엔진 |
|---|---|---|
| 이미지: jpg png webp heic tiff avif bmp svg | jpg png webp heic tiff avif bmp + **pdf** (자기 형식 제외, svg는 입력만) | Magick.NET |
| gif | 비디오 형식들 (원작과 동일) | ffmpeg |
| pdf | **jpg png** (페이지별), docx, txt | jpg/png: `Windows.Data.Pdf` 또는 PDFium 렌더(150 DPI 이상, 구현자 재량) / docx: Word(PDF 열기→저장) / txt: 텍스트 층 추출 |
| 오디오: mp3 m4a wav flac ogg opus aiff wma | 오디오 형식끼리 | ffmpeg |
| 비디오: mp4 mov mkv webm avi wmv | 비디오 형식끼리 + gif + mp3 (webm은 입력만) | ffmpeg |
| 문서: docx doc rtf odt txt md html | 서로 + pdf (doc·rtf는 입력만) | Word COM. md는 Markdown→HTML로 바꾼 뒤 Word로 처리, →md는 구현자 재량(최소: 문단·제목·목록·굵게/기울임) |
| 슬라이드: ppt pptx odp | pdf, jpg, png (+ ppt→pptx) | PowerPoint COM. jpg/png는 슬라이드별(§5.0 폴더 규칙) |
| 스프레드시트: xlsx xls ods csv tsv | 서로 + pdf (xls는 입력만) | Excel COM. csv/tsv는 첫 시트, UTF-8 |

- HEIC/AVIF 쓰기가 Magick.NET에서 안 되면 해당 대상만 빼고 그 사실을 기록한다.
- 이미지 → PDF: 이미지 한 장 = 한 페이지, 이미지 원래 크기 비율 유지.
- 변환 품질 기본값(JPG 품질 등)은 원작 `Sources/Windows/FormatSettingsView.swift`·`AppSettings.swift` 기본값을 따른다. 설정 UI는 만들지 않는다.

### 5.2 도구 휠 (Alt)

| 도구 | 대상 | 동작 |
|---|---|---|
| 압축 | 이미지(jpg png webp heic tiff avif bmp) | 옵션 창: 원작처럼 프리셋 / 목표 파일 크기 / 비율 + 최대 해상도(원본·2560·1920·1280px). 원작 `ToolOptions.swift` `SizeGoal`, `ResizeCap` 참고. 결과 `(compressed)` |
| 자르기 | 이미지 | 편집 창: 이미지 위 드래그 사각형, 비율 프리셋(자유·1:1·4:3·16:9 등), 정확한 픽셀 입력. 결과 `(cropped)` |
| PDF 만들기 | 이미지 여러 개(1개도 가능) | 옵션 창에서 순서 확인·변경 후 PDF 하나로. 이름은 첫 파일 기준 `(merged)` 또는 구현자 재량 |
| 합치기 | PDF 2개 이상 | 순서 확인·변경 후 하나로. `(merged)` |
| 나누기 | PDF | 쪽마다 한 파일. `이름 (pages)` 폴더 |
| 글자 복사 (OCR) | 이미지, PDF | §5.4 |
| 배경 제거 | 이미지 | §5.4 |

- 이미지 여러 개를 끌면 압축은 일괄 처리, 자르기는 첫 장 기준 편집 후 전부 적용 또는 하나만 허용(구현자 재량, 정한 것을 기록).
- 꽃잎 구성은 원작 `LimeTool.tools(for:)`처럼 파일 종류·개수에 따라 달라진다.

### 5.3 액션 휠 (Ctrl)

| 액션 | 동작 |
|---|---|
| 선반 | 드롭한 위치에 떠 있는 작은 카드에 파일을 올려둔다. 카드에서 다시 끌어 다른 곳에 놓을 수 있다(여러 개 한 번에), 파일을 더 끌어 넣을 수 있다, 이동·닫기 가능. 원작 `Sources/Windows/Shelf.swift`의 핵심만 — 아이콘/목록 보기 전환, 화면 가장자리 붙기, 미리보기는 비목표 |
| 복사 | 파일들을 클립보드에 (탐색기에서 Ctrl+V로 붙여넣을 수 있는 형태) |
| 이동 | 폴더 선택 창 → 그 폴더로 이동. 이름 겹치면 번호. 자기 자신 안으로 이동 금지 (원작 `OperationCoordinator.move`) |
| 경로 복사 | 전체 경로를 줄바꿈으로 이어 클립보드에 |
| 터미널 | 첫 파일이 있는 폴더(폴더면 그 폴더)에서 Windows Terminal(`wt`), 없으면 PowerShell |

### 5.4 품질 조건부 기능

**글자 복사 (OCR)**
- PDF에 텍스트 층이 있으면 그것을 쓰고, 없는 쪽만 OCR (원작과 동일).
- 엔진: 우선 Windows 내장 OCR(`Windows.Media.Ocr`). 지금 PC엔 한국어만 설치돼 있으므로 영어 혼합 문서 품질을 확인하고,
  필요하면 영어 언어팩 설치 안내를 띄운다.
- 결과는 즉시 클립보드 + 결과 창(복사·`(text).txt` 저장 버튼).
- **품질 기준:** 사용자가 준비한 실제 샘플(한글 스크린샷, 한영 혼합 문서, 스캔 PDF)로 사용자가 보고 "쓸 만하다"고 해야 넣는다.
  내장 OCR이 미달이면 PaddleOCR 같은 대안을 검토하고 사용자에게 돌아온다.

**배경 제거**
- 엔진: BiRefNet 계열 ONNX 모델 + ONNX Runtime(GPU 가속: DirectML 또는 CUDA, 구현자 재량, CPU 폴백).
- 모델은 앱에 포함하지 않고 **처음 쓸 때 내려받는다**(진행 표시, 취소 가능). 모델 라이선스를 확인하고 고지에 넣는다.
- 결과: 투명 PNG `(no background).png`.
- **품질 기준:** 사용자 샘플(인물, 동물, 물건)로 사용자가 "맥 수준"이라 판단해야 넣는다.

## 7. Office 자동화 규칙
- Word/PowerPoint/Excel은 **보이지 않게** 새 인스턴스로 띄우고, 경고·대화상자 끄기(`DisplayAlerts` 등),
  읽기 전용으로 열고, 끝나면 문서를 닫고 **우리가 띄운 인스턴스만** 종료한다. COM 객체는 확실히 해제한다.
- 시간 제한(예: 2분)을 넘기면 우리가 띄운 프로세스만 정리하고 실패 처리.
- 같은 Office 앱 작업은 동시에 하나씩(직렬화).
- 암호 걸린 문서, 매크로 문서는 열지 말고 실패 처리.
  *(구현자 판단으로 정함)* 옛 이진 형식(.doc/.xls/.ppt)은 매크로가 있는지 열어 보기 전엔 알 수 없으므로
  **매크로 강제 비활성(`AutomationSecurity = msoAutomationSecurityForceDisable`)으로 열고**, 매크로 코드가 있으면 닫고 실패 처리한다.
- *(구현자 판단으로 정함)* **PowerPoint는 단일 인스턴스**라 새 인스턴스를 띄울 수 없고 창을 숨길 수도 없다.
  그래서 사용자가 이미 PowerPoint를 열어 두었으면 그 인스턴스 안에서 **창 없이**(`Presentations.Open(..., WithWindow: false)`) 열어
  변환하고, 우리가 연 프레젠테이션만 닫는다. 사용자의 PowerPoint는 절대 종료하지 않는다. 시간 제한을 넘기면 강제 종료 없이 실패 처리만 한다.
  PowerPoint가 꺼져 있었으면 우리가 띄우고, 끝났을 때 **열린 프레젠테이션이 하나도 없을 때만** 종료한다.
- *(구현자 판단으로 정함)* Word/Excel도 같은 원칙: 종료 직전에 우리가 열지 않은 문서가 그 인스턴스에 들어와 있으면
  (사용자가 그 사이 더블클릭한 파일이 붙은 경우) **종료하지 않고 연결만 끊는다.** 사용자 문서를 닫는 일은 어떤 경우에도 없다.
